# Code review of bsce (paper_test version + NF-LADMM-SR), 15 Oct 2026

**Scope.** I reviewed the code that produces the paper results:
- data generation and test noise;
- evaluation and `compare.py`;
- the training loop, protocols, fine-tune, suite and `promote_layer.py`;
- every model and classical baseline.

Each finding below was reproduced with code; candidates that could not be demonstrated were dropped. "Fixed" means changed in `bsce_code_14`, with a test that fails on the old code and passes on the new one.

**Bottom line.**
- **Nothing found changes the published comparison numbers you already have** (LADMM T6/T4 and the authors' GM-LAMP/LAMP).
- **Four defects could have affected new runs, and are fixed:**
  - NF-LADMM trained with gradient clipping under the "common" protocol (unfair);
  - a resumed run was not the same network;
  - the suite silently reused fine-tunes made with another budget;
  - `make_dataset --force` silently kept measurement files that belonged to the old channels.
- **One item must be stated in the paper:** NF-LADMM is given the true noise variance at test time.

## 2. Not changed (state them, or know them)

| # | what | why not changed / what to do |
|---|---|---|
| N1 | **NF-LADMM gets the true noise variance σ² at test time** (`sigma: known`). The other learned methods estimate the noise level from the residual. | A design choice, but **state it in the paper**. For a strictly blind comparison, also run the residual variant: `run_suite.py ... --methods nfladmmsr --set model.sigma=residual` (folder `NF-LADMM-SR-T4_sigma-residual`). |
| N2 | GM-LAMP's mixture likelihood uses exp(−\|d\|²/(2s))/(2πs) with s the complex variance ‖v‖²/M. The exact circular-complex density is exp(−\|d\|²/s)/(πs). | Inherited from the authors: bsce reproduces `GM_LAMP.m` to 4.6e-15, so the port is faithful. Keep it as the baseline; just don't call it the exact MMSE. On a toy prior the exact form is about 1.8 dB better. |
| N3 | The fine-tune uses the same seed for both bands, so both see the same minibatch indices and the same raw noise, scaled to each band. | Common random numbers: no bias, but the bands are not independent. Fine as is. |
| N4 | The fine-tune always uses the NMSE loss. With `--protocol paper`, NF-LADMM is trained with log-NSE and fine-tuned with NMSE. | Under the default common protocol all methods use NMSE everywhere, so this only affects `--protocol paper`. |
| N5 | Kronecker LADMM: the Van Loan init fits H1⊗H2, but the forward pass applies H2⊗H1. | Inherited from your original script. For a random A the fit error barely changes (0.415 vs 0.413). Only matters if A had Kronecker structure. |
| N6 | `soft_wei` (LAMP) gives NaN for an exactly zero input column. | Cannot happen with noisy data; kept to stay bit-identical with the TF original. |
| N7 | The SD baseline uses a 1-D window of V = 8 indices, also on the UPA grid (not 2-D). | Faithful to `SD.m`, which was written for the ULA. Label it "SD (1-D window)" in UPA tables. |
| N8 | `deepmimo_convert.py` with several overlapping `--input` files does not remove duplicate users, so a test user can stay in training. | Not in your path: GM-LAMP data use one `H_*.mat`, and `make_dataset.py` already removes duplicates. Use `make_dataset.py` for multi-file inputs. |
| N9 | The training measurement noise seed depends on the script that made the file: `train.py` uses 0, `make_dataset.py` uses `--seed` (2026). | Each path is deterministic, so two computers that follow the same path get the same files. Copying `data/` is the safe way (GUIDE 4.4). |
| N10 | The test noise seed is `scenario seed + 1000 + i`, and `evaluate.py --n-test k` noise is not a subset of the full test noise. | All paper scenarios use seed 2026 and the full 2000 test channels. A different scenario seed changes AMP by ≤ 0.02 dB. Keep it, so existing results stay valid. |

## 3. Checked and correct (no change needed)

**Data**
- **Noise model:** y = A(x + n) on every path; σ² = 10^(−SNR/10), split σ²/2 per real/imaginary part (measured 0.09999 / 0.04999 at 10 dB); ‖x‖² ≈ N.
- **Test noise:** the same for every method. It is drawn once per SNR, before the method loop, on all 2000 channels, so it does not depend on method order or batching.
- **Band selection:** 10 dB goes to the 10–20 dB network and 20 dB is included. A one-network folder and a band pair are each evaluated with their own networks.
- **NMSE:** the pooled ratio in `evaluate.py`, `depth_snapshots.py` and the fine-tune validation.
- **Seeds:** train/val/test channel seeds are disjoint, and band seeds do not collide. The standard SV test set is identical in `make_dataset` and `generate_data`.
- **DeepMIMO:** test users are removed from train/val; normalisation ‖x‖² = N.

**Models**
- **LAMP / GM-LAMP Onsager terms:** match finite-difference Wirtinger derivatives to 1e-11.
- **GM float32 fix:** outputs and gradients within 3e-6 of float64, with no NaN, for inputs scaled from 1e-3 to 30.
- **LADMM:** updates and init; the operator variants and their parameter counts; tied/untied.
- **NF-LADMM:** the A⁺ step and both updates.
- **LVAMP:** the complex BG posterior.
- **UPA beam ordering** is consistent in the data, group threshold, Kronecker prior and CNN.

**Training**
- Protocol merge (now including `grad_clip`), refinement stages (new parameters, then all), early stopping and `restore_best`.
- The NF-LADMM layer-wise plan: future layers get zero gradient and stay unchanged.
- `truncate_model` and `promote_layer`: a T-layer snapshot equals a direct T-layer run (difference 0) for LADMM, LAMP, LISTA and NF-LADMM-SR.
- Fine-tune data and scenario detection, and the checkpoint hash.
- `device.py` determinism.

## 4. Effect on what you have
- **Your existing networks and tables:** none of the fixes changes them.
  - F1 matters only for NF-LADMM trained with a common protocol (new runs).
  - F2 matters only for runs that were interrupted and resumed. Such a network is still valid, just not bit-identical to an uninterrupted one.
  - F6 and F7 change only the parameters column.
- **Before you compare**, check your fine-tune budgets: the earlier runs mixed 15k and 20k iterations. With F3 the suite now stops on such a mismatch instead of mixing them.
