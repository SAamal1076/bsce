# Code review of bsce v31.2, 21 Oct 2026

**Scope.** The whole library (`bsce/`), the training, evaluation and comparison scripts, and the workbench (`app/`).
Every finding below was reproduced with code before it was fixed; candidates that could not be demonstrated were
dropped. Findings of `REVIEW_2026-10-15.md` were not re-reported. Each fix has a test in
`tests/test_review_2026_10_21.py` that fails on v31.2 and passes now.

**Tests after the fixes** (CPU, GNU Octave, TensorFlow 2.21, all four reference zips, SV_ULA / SV_UPA data made
with `make_gmlamp_data.py`, fingerprints OK): **516 passed, 0 failed**, including every comparison with the original
MATLAB / TensorFlow code and `test_ladmm_best_vs_untitled2.py`. Not run: the GPU test (no CUDA here), the
QuaDRiGa / Sionna 3GPP generators, one test that needs the DeepMIMO data, and one skipped by design.

**Bottom line.**
- **No error in the estimator maths.** LAMP / GM-LAMP, LADMM, Graph-LADMM, LISTA / ALISTA, LVAMP, CADMM, NF-LADMM,
  AMP and OMP all matched their references or an independent derivation. The data generators (SV, 3GPP, the noise
  models, the SNR draws, the seeds) are correct.
- **Training (end-to-end schedule):** `grad_clip` was ignored, and `restore_best` with `lr_list` could return weights
  worse than the ones a stage started from. This affects ADMM-Net and UTRR runs only.
- **Tables:** compare.py crashed with the `l1` / `grwl1` baselines and misaligned `summary.csv` when scenarios have
  different test SNRs. NF-LADMM's MACs column was 2× too high.

## 1. Fixed

| # | severity | file | problem | fix |
|---|---|---|---|---|
| R1 | **medium (fairness)** | `bsce/train/trainer.py` `_run_end2end` | `grad_clip` was never applied in the `end2end` schedule, so ADMM-Net / UTRR runs named `_clip1` were not clipped (weight change identical with clip 1e-9 and no clip). | Clip the gradient norm before `opt.step()`, as in the other schedules. |
| R2 | **medium** | `bsce/train/trainer.py` `_run_end2end` | With `lr_list` + `restore_best`, each stage restarted its best at +inf and never validated its starting weights, so a later stage could return weights worse than the previous stage's best (−2.75 dB → +0.55 dB in a forced example). | A later `lr_list` stage validates its starting weights and keeps them unless an epoch beats them (saved in the checkpoint as `keep`). Patience and early stopping are unchanged. |
| R3 | minor | `scripts/train.py` | `final_val_nmse_db` was the last epoch's NMSE, not that of the restored (saved) network; `select_depth.py` and `runs.py` read it. | The last layer's value after restore (`_final_nmse_db`). |
| R4 | medium (crash) | `scripts/compare.py` | `--classical` with `l1`, `grwl1` or `admm`: `KeyError` when drawing the figure (no colour). | Colours for every classical method. |
| R5 | medium (tables) | `scripts/compare.py` | `summary.csv` took the SNR columns from the first scenario only; a scenario with other test SNRs wrote its values under the wrong headers. | Columns = union of the test SNRs; each value goes under its own SNR (empty where a scenario has none). |
| R6 | minor (cost column) | `bsce/cost.py` | A real matrix cast to complex (NF-LADMM's A, A⁺) was counted as complex × complex (×4) instead of real × complex (×2). LAMP / LADMM were already counted ×2. | ×4 only when both operands have a non-zero imaginary part, ×2 when one has. LAMP, LADMM and Graph-LADMM counts are unchanged. |
| R7 | minor (MATLAB) | `bsce/export.py` | A group-threshold LADMM (`group`, `group_k`, `group_kc`) got an `_orig.mat`, but `LADMM_test.m` applies the scalar soft threshold only, so MATLAB gave a wrong estimate (relative error 0.75). | `_orig.mat` only for `threshold: scalar`. |
| R8 | low | `bsce/models/graph_ladmm.py` | `edge_phase: theory` set −π/N2 on both axes of a UPA; axis 0 has N1 beams (−π/N1). Only differs when N1 ≠ N2. | Phase per axis. |
| R9 | minor (crash) | `scripts/generate_data.py` | Bands with `val_range` (e.g. `sv_ula_user.yaml`, and every yaml written by `make_dataset.py --snr`) raised `KeyError: 'val_snr'` after writing the training file. | Validation SNRs drawn per chunk over `val_range`. |
| R10 | minor (crash) | `bsce/config.py` | `--set train.steps=2e4` gave the float 20000.0 (`range()` / `randint` then fail), and e-notation inside lists stayed strings (`refinements=[5e-1,1e-1]`). | Integer e-notation → int; lists and dicts converted too. |
| R11 | minor | `scripts/aggregate_seeds.py` | `<run>_s1+polish` was not grouped with `<run>+polish`. | Strip the polish suffix before dropping the seed. |
| R12 | minor (crash) | `scripts/check_combiners.py` | `IndexError` when nothing could be evaluated on any combiner. | Stops with a message. |
| R13 | cosmetic | `scripts/evaluate.py` | `l1` / `grwl1` drawn as solid lines like networks. | Use `classical.METHODS`. |
| R14 | tests | `tests/test_v30_combiners_names.py`, `tests/test_v31_release.py` | Five tests failed (not skipped) before `make_gmlamp_data.py` had created `data/SV_ULA/CSmatrix.mat`. | Fall back to the same matrix in `reference/gmlamp/CE_SV/CSmatrix256128.mat`. |

## 2. Not changed (know them, or state them)

| # | what | why not changed / what to do |
|---|---|---|
| K1 | **ADMM-Net's MACs per channel include T inverses of N×N matrices** that do not depend on the input (1.0e9 at batch 1 vs about 4e6 with the exported `Winv_t`). The same holds for LADMM `psd` / `kronprior` / `diagprior`. Graph-LADMM caches its H_t, so it is not charged. | A choice of convention: either cache the inverses at inference (as Graph-LADMM does) or state in the table that factorisations are charged per call. |
| K2 | With `--noise online` and `val_mean_db`, the validation groups are random mixtures of SNRs, not SNR chunks. | Only affects that combination; early stopping uses a slightly different metric than printed. |
| K3 | The last-layer α of every LADMM never receives a gradient but is created and counted. | Faithful to the original scripts. |
| K4 | `finetune_bands.py` fine-tunes a `combiner: mix` source on the scenario's fixed combiner without a message. | Intended, but worth a printed note. |
| K5 | The workbench's `/api/exists` accepts absolute paths outside the package (token-protected, local only). | Needed for paths the user types (DeepMIMO, Octave). |

## 3. Checked and correct
- **Data:** steering vectors and Kronecker order, the DFT / lens matrices, column-major RNG fill,
  σ² = 10^(−SNR/10) split per real/imaginary part, the whitening map, 3GPP TR 38.901 formulas and correlation matrices.
- **Models:** save/load, truncation and `set_combiner` round trips (differences 0), the inference cache, dtypes,
  batch size 1, parameter counts.
- **Training:** validation under `no_grad`, the cosine schedule, early stopping and resume, Adam state per stage.
- **Evaluation:** pooled NMSE, band choice at the boundaries (10 dB → the 10–20 dB network, 20 dB included), polish
  K / ε chosen on validation.
- **Workbench:** binds to 127.0.0.1, checks the Host header and a token, runs commands as argument lists (no shell),
  `/file` is confined to the package, no XSS in `app.js`.
